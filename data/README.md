# 内置示例岗位数据

`preset-backup.json` 是插件首次安装时自动导入的默认岗位备份，也是「设置 · 备份与恢复 → 导入内置岗位」的数据源。

## ⚠️ 全部为虚构示例数据

| 项 | 当前值 |
|---|---|
| 公司名 | `示例科技（Example Tech）` |
| 默认岗位 | `示例·嵌入式软件工程师` |
| 岗位数量 | 26 个，标题统一以 `示例·` 开头 |
| JD 正文 | 标注「虚构数据，非真实招聘信息」 |
| 薪资 | 演示用数值（`15-25K·12薪` 等） |
| 城市 | `北京|上海` |
| 年龄 / 第一学历硬门槛 | **不预置**（`ageMax: null`） |
| AI 配置 | 端点、模型、密钥全部为空，默认关闭 |
| 导出时间 | `2026-01-01T00:00:00.000Z`（占位） |

**不含**：真实企业名称、真实在招岗位、真实薪资、客户信息、内部系统名、候选人姓名 / 电话 / 邮箱 / 证件号。

## 换成你自己的配置

1. 在扩展「设置」中修改公司名、岗位、筛选条件与话术；
2. 用「设置 · 备份与恢复 → 导出」生成你自己的备份文件；
3. 把导出的 JSON 覆盖本文件（保持 `type: "settings-backup"`、`format: 1`、`jds` 数组结构不变），或直接在设置页导入；
4. **导出前先脱敏**：确认不含真实个人信息、客户名称与内部地址，再提交到任何公开仓库。

## 结构说明

```jsonc
{
  "type": "settings-backup",   // 代码据此判断文件类型，勿改
  "format": 1,                 // 备份格式版本，勿改
  "settings": { /* 默认设置 */ },
  "jds": [ /* 岗位数组，每项需含 id / title / base / schema 等字段 */ ]
}
```

`settings.greetOrder` 中的 ID 应与 `jds[].id` 对应；`settings.activeJdId` 应指向其中一个岗位。新增或删除岗位时请一并更新这两处。

## 验证

本仓库的 CI（`.github/workflows/manifest-check.yml`）会校验本文件的 JSON 合法性、示例标记，以及 `lib/VENDOR.json` 中第三方库的 SHA256。
