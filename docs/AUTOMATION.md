# 自动化能力说明与风险提示

本文件说明开源版**保留**的自动化能力、其工作方式，以及使用者需要自行承担的责任。按项目决定，这些功能未做删减；本文件只做披露，不构成使用建议或法律意见。

## 1. 保留了什么

| 能力 | 实现位置 | 说明 |
|---|---|---|
| 自动打招呼 / 智选 | `content/boss-greet.js`、`content/boss.js`、`content/liepin.js`、`services/engine.js` | 在招聘站点逐张读取候选人卡片或会话，按岗位计划判定后执行后续动作 |
| 拟真节拍与每日上限 | `services/rhythm.js`、`options/rhythm-card.js` | 可调秒/个、随机浮动、拟人小憩、每日总上限（默认 180） |
| 职位抓取与发布 | `content/job-fetch.js`、`content/job-publish.js` | 从平台读取职位 JD 生成导入表，部分场景可回填发布 |
| 计划任务 | `services/scheduler.js`、`options/sched.js` | 定时按序执行打招呼 / 智选等步骤 |
| 页面主环境注入 | `content/open-hook.js` | 在猎聘以 `MAIN` world 临时接管 `window.open` 与链接点击，把新标签地址交给扩展后台 |
| 本机 RPA 助手 | `rpa-helper/` | Python 实现，仅监听 `127.0.0.1:17861`，模拟真实鼠标键盘；安装脚本写 `HKCU\...\Run` 开机自启 |
| CDP 输入 | `background.js`（`chrome.debugger`） | 部分执行模式下通过 `Input` 域发送鼠标事件 |

## 2. 使用者需要自行评估的三类风险

### 2.1 第三方平台服务条款

批量自动打招呼、自动索要/拒绝简历、抓取职位、拟真节拍等行为可能违反 BOSS 直聘、猎聘等平台的用户协议或风控规则，可能导致账号限制、功能失效或法律争议。**开源会公开这些实现细节**，请在使用前自行确认平台授权与合规边界。项目作者不对任何具体使用方式作背书。

### 2.2 浏览器商店审核

`debugger`、`management`、全站 `optional_host_permissions`、`http://127.0.0.1/*` 以及 MAIN world 页面 API 覆盖，均属高权限组合，通常会进入人工审核。提审材料见 `PERMISSION_JUSTIFICATION.md` 与 `PRIVACY.md`。若商店被拒，可考虑将本仓库作为「源码分发」渠道，通过 GitHub Release 的 zip 自行加载，不依赖商店。

### 2.3 企业安全策略

开机自启 + 无窗口后台进程 + 本地监听端口 + 输入模拟，是多数 EDR / 终端管控策略的重点关注组合。部署前请：

- 由 IT / 安全部门评估并按需加白名单；
- 明确告知使用者助手的存在、作用与退出方式；
- 确认 `stop_rpa_helper.py` / `remove_autostart.py` 可用；
- 在内网环境优先使用「加载已解压扩展 + 关闭 RPA」的纯本地模式。

## 3. 可控开关

- 运行模式：停止 / 试运行 / 正式运行（三态）；
- 计划任务、各平台打招呼与智选均可独立关闭；
- RPA 助手不安装即不启用；已安装可停止并取消自启；
- AI 判断默认关闭；
- 扩展卸载会清除本机全部数据（卸载前请先做加密备份）。

## 4. 与「辅助决策」原则的关系

自动化只负责**执行**，不负责**作决定**。判定仍由可解释规则产生，不合格默认进入「待确认」由 HR 确认。详见 `MODEL_CARD.md` 第 7 节。建议始终保留人工复核环节，不要将本工具直接对接自动拒绝逻辑。
