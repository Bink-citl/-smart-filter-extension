# 评分与决策规则卡

**版本**：3.6.0 ｜ **更新日期**：2026-11-08
**用途**：向 HR、业务方、企业法务与安全评审说明「判定如何产生、有哪些局限」。这是「可解释 + 可审计」承诺的书面依据。

## 1. 类型

确定性规则引擎 + 可选 AI 辅助（默认关闭）。AI 仅用于文本理解辅助，**不单独作出淘汰决定**。规则版本随每条决定记录保存，保证历史结果可复现。

## 2. 输入与输出

- 输入：岗位描述与筛选条件、候选人卡片 / 在线简历 / 简历文件文本、岗位知识库（行业别称与相近方向）、用户可配置权重。
- 输出：合格 / 待复核 / 不合格（或分数）、命中与未命中条件、判定原因片段、规则版本、决定记录 ID。

## 3. 判定维度

| 维度 | 依据 | 可配置 |
|---|---|---|
| 岗位相关性 | JD 硬性关键词与候选人工作经历的匹配 | 是 |
| 做过本岗位 | 历史职位与目标岗位的一致程度 | 是 |
| 期望一致性 | 期望职位 / 城市 / 薪资与 JD 的匹配 | 是 |
| 岗位知识库 | 行业别称、相近方向归一化后参与匹配 | 是（可增删方向） |

## 4. 不使用 / 不预置的特征

**不得参与评分**：性别、婚育、民族、宗教、健康、籍贯、户籍、照片、姓名用字。

**开源版不预置**：年龄上限、第一学历门槛、院校排名。`data/preset-backup.json` 中 `ageMax` 为 `null`、`ageFilled` 为 `false`，`services/store.js` 的 `baseDefaults.ageMax` 同样为 `null`。产品已有「岗位编辑页检测到性别、婚育、民族、宗教、健康条件时提示删除」的设计。

使用者若自行配置年龄或学历条件，应自行评估就业歧视相关法规并承担责任。

## 5. 评测与回归

- 评测集：对判过的卡片标「该不该打」、对判过的会话标「合不合格」，计算**漏打率 / 误打率**。
- 盲测复核：随机抽样重新盲标，计算标注一致率。
- 规则改动应重跑评测，指标不得劣于基线。
- 建议在公开合成数据集上发布基线结果，提升可复现性。

## 6. 已知局限

- 基于文本与规则，无法评价项目复杂度、团队规模与实际业务成果。
- 扫描件依赖 OCR，识别错误会传导到判定；无文本层 PDF 可能抽取为空。
- 招聘平台改版会导致字段读取失效；项目通过选择器配置与兜底逻辑缓解，但不保证长期稳定。
- 岗位知识库人工维护，存在漏召回 / 误召回；垂直术语需使用者补充。
- **本工具不预测候选人未来工作表现，也不构成录用建议。**

## 7. 人在回路与审计

1. 不合格默认进入「待确认」，HR 确认后才执行后续动作；不自动淘汰。
2. 每判定一人生成决定记录：时间、平台、模块、岗位、结论、原因、依据片段、规则版本、试运行/正式、执行动作。
3. 决定明细保留 90 天，月度汇总仅数字保留 3 年；候选人可要求一次删除全部信息。
4. 人才库按期限自动删除（不合适/未沟通 180 天，收到简历未面试 1 年）。
5. 最终招聘决策始终由人工作出，并保留决策记录。

## 8. 自动化边界

发布包中的可选自动化模块（自动打招呼、自动索要/拒绝简历、职位抓取、拟真节拍、本机 RPA 真实鼠标键盘、`chrome.debugger` CDP 输入）按项目设计**予以保留**，但可能涉及第三方招聘平台服务条款与浏览器商店政策。详见 `AUTOMATION.md`；使用者需自行确认平台授权与当地法律要求。

## 9. 变更记录

判定维度、默认阈值或保留期限的任何变更写入 `CHANGELOG.md` 并提升次版本号。
