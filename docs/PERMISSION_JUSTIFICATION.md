# 权限逐项说明（Chrome 网上应用店提审材料）

按项目决定，以下权限**全部保留**。本表用于向审核方说明每项权限的实际用途；提交商店时需保证 `manifest.json` 声明、代码实现、「数据使用声明」与 `PRIVACY.md` 四处一致。

| 权限 | 代码中的实际使用 | 提审理由 |
|---|---|---|
| `storage` | `background.js` 等大量 `chrome.storage.local` | 在用户本机保存岗位 JD、筛选规则、设置与决定记录，不上传 |
| `unlimitedStorage` | 简历元数据与人才库本地累积 | 本地保存用户主动收集的简历索引与决定记录，避免配额导致数据丢失 |
| `downloads` | `background.js`、`services/exporter.js` | 导出用户主动请求的报表与按规则命名保存简历文件 |
| `tabs` | `background.js`、`popup/popup.js` 等 | 定位用户当前打开的招聘网站标签页以展示浮层 |
| `scripting` | `background.js` | 在用户主动启用时注入浮层脚本 |
| `alarms` | `background.js`、`services/scheduler.js` | 计划任务与保留期限每日检查 |
| `offscreen` | `background.js` | 在离屏文档解析 PDF 文本，避免阻塞界面 |
| `debugger` | `background.js` 中 `chrome.debugger.attach` + CDP `Input` 域 | 在部分执行模式下通过浏览器调试协议发送真实鼠标事件以完成自动化；操作结束后立即释放调试会话 |
| `management` | `services/scheduler.js` | 查找/唤起配套工作台扩展，读取其只读状态用于「简历分发」页展示 |
| `host_permissions`（招聘站域名） | 内容脚本读取页面文本 | 仅在用户主动进入这些招聘站点时读取岗位与候选人信息 |
| `http://127.0.0.1/*` | `background.js` 与本机 RPA 助手通信 | 本地回环，不访问外网；助手由用户手动安装，可随时停止 |
| `optional_host_permissions` | `options/options.js` 运行时申请 | 仅在用户主动配置自定义 AI / 选择器端点时按需申请，未授权前不生效 |

## 单一用途声明（建议稿）

> 本扩展在浏览器本地解析简历与岗位描述，给出可解释的匹配评分，并生成可审计的判定记录，辅助招聘人员完成简历初筛；自动化执行与报表导出均为该用途下的可选执行方式。所有候选人数据默认仅保存在用户本机。

## 2026 年商店需额外准备的披露

- **AI 功能披露**：AI 判断默认关闭、发送前去标识、用户自配端点、可随时关闭 —— 在商店描述与扩展 UI 中显著说明并允许退出。
- **数据使用声明**：启用 AI 时存在「用户提供的文本传输至用户自配第三方端点」，不得勾选「不收集任何数据」；本地回环通信需单独说明。
- **逐权限理由**：每项填写具体功能，不要使用通用套话；空泛或与代码不符是常见驳回原因。
- **截图**：至少 1 张 1280×800 或 640×400 的真实界面截图，不得使用设计稿，且不得出现真实候选人、公司名或薪资。
- **联系邮箱**：在 Chrome 开发者信息中心左侧 **Account** 页填写并验证，否则无法提审。
- **常见驳回**：权限未在代码中使用、隐私政策与声明不一致、远程代码、单一用途不清、多用途描述。

> Google 未公布审核算法；上述为公开政策与开发者社区通行做法，最终以 Chrome Web Store 开发者政策页与审核反馈为准。若审核受阻，可改用 GitHub Release zip 自行分发。
